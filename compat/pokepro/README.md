# 专业戳一戳兼容补丁

适用于 [Zhalslar/astrbot_plugin_pokepro](https://github.com/Zhalslar/astrbot_plugin_pokepro) 的 **v2.1.1** 本地安装版本，使用 AstrBot **4.29.1** 验证。补丁基线以 [baseline.json](baseline.json) 中四个源文件的 SHA-256 为准；版本号相同但文件不同的安装也必须先核对差异，不能盲目覆盖。

## 修复内容

- **定时目标**：将完整目标账号作为单项列表传入发送器，避免字符串被逐个字符发送。
- **缺失表情命令**：随机选中的命令如果没有已启用的处理器，复用插件原有的“被戳”模型回复。命令文字不会成为发给模型的提示。检查使用 AstrBot 的命令注册表、会话插件开关和实际命令名/别名/正则；已匹配但权限不足的命令仍由正常消息流程拒绝，不回退模型。
- **发送结果**：按平台实际成功次数报告“已戳”。全部失败明确返回失败，部分成功报告实际次数并保留原有错误日志。

补丁不更改随机权重、目标名单、禁言设置、图库或定时时间。Codex 桥接对公共工具的当前群和成员检查在桥接自身实现，不能用本补丁替代权限检查。

## 应用

1. 备份插件目录和配置，检查 [baseline.json](baseline.json) 的源文件哈希。
2. 在 `astrbot_plugin_pokepro` 插件目录运行 `git apply --check <补丁文件路径>`，成功后运行 `git apply <补丁文件路径>`，其中补丁文件为 [changes.patch](changes.patch)。检查不通过时，先比较安装版本差异。
3. **核对定时目标**：上游默认示例名单不能直接用于真实发送。没有配置实际目标时，应关闭定时戳；只启用已明确配置的群和成员。
4. 停止并重新启动 AstrBot，NapCat 可以保持运行，以重新载入插件代码和定时配置。

日常被戳触发的模型请求使用 AstrBot 的常规模型流程，可继续使用当前选中的本机 Codex 提供商。没有预录语音池时，插件自身的“随机语音”分支仍需要单独配置；桥接的 `send_voice` 是另一个能力。

## 验证范围

在 AstrBot Python 环境中，从打过补丁的插件目录运行：

```text
python -m unittest discover -s tests -q
```

12 项回归测试通过，覆盖真实发送器和调度函数、完整账号、多目标和重复次数、全部失败和部分失败、缺失命令、禁用插件/处理器/会话、正则命令，以及真实 `WakingCheckStage` 的管理员权限拒绝。所有 QQ 接口均使用测试替身，没有发送真实消息或戳一戳。

另有隔离集成验证确认“戳一戳”通知无需 `@` 即可经 AstrBot 消息阶段进入桥接提供商，并到达回复发送阶段；模型输出和发送器使用替身。真实账号上的平台风控、成员权限和发送结果仍需重启后按实际使用验证。
