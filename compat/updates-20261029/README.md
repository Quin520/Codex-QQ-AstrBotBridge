## 模型与配置

- 在 AstrBot 中配置 API 模型，桥接选择 `model_backend=api` 和对应 `api_provider_id`。桥接继续启用，内部 ID 与数据目录保持原样。
- 将其他插件显式引用的 `local_codex` 切换为选定 API，清理不再使用的 CLI 提供商。保留 API 凭据、Embedding 提供商及其原索引、Edge TTS 与 RVC 环境。
- API 模式隐藏 CLI 的路径、Fast、推理与队列参数；API 的推理参数在 AstrBot 模型配置中维护。聊天与视频识图走该 API，联网搜索使用 Responses Web Search，生图使用 Images API。生图需要账户拥有所选图像模型权限。
- 主动消息配置 `group_only_mode=true` 后，AstrBot 配置和独立面板均隐藏私聊控制，状态列表仅显示群聊，旧私聊任务也不会恢复执行。保留群聊的随机间隔和目标群配置。
- 群共享上下文、个人会话、成员设定、长期记忆、待审核记录和已启用表情包库均不需要迁移或清空。`/new` 继续只新建当前个人会话。
- 好感度审批仍有独立开关，默认关闭；学习内容审批不受影响。上游新增好感度作用域后，审批会核对提案所用作用域，切换作用域不会把旧提案写进另一份好感度。

## 应用与回滚

1. 保存当前源码、本地适配、全部配置和数据备份。运行中的 SQLite 应使用在线备份接口；停止后再保存一份最终快照。
2. 在独立目录检出 `baselines.json` 对应提交，执行 `git apply --check <补丁路径>`，再执行 `git apply <补丁路径>`。核心的 `core.patch` 基于 AstrBot 4.29.3。
3. 安装各组件声明的依赖。表情包管理器新增 MinIO 依赖；只安装缺少的依赖，不需要重建 RVC 或记忆模型环境。
4. 自学习补丁包含前端源码，需要在 `web_src` 执行 `npm ci`、`npx tsc --noEmit`、`npm test -- --run` 和 `npm run build`，一并部署生成的 `web_res/static/dashboard`。其他需要构建的前端按各插件说明操作。
5. 停止 AstrBot，替换已验证的源码和前端产物，再应用少量配置修改；保留原文件编码、换行和数据目录。NapCat 可保持运行。重新启动 AstrBot，检查插件加载、模型选择及主动消息计时。
6. 回滚时先停止 AstrBot，按安装清单恢复原源码、前端、依赖和配置。如果新版已写入或迁移数据库，另行核对数据库版本再恢复快照，避免误覆盖新聊天。

补丁不包含 API Key、QQ 号、群成员设定、登录 Cookie、聊天数据或本地数据库。部署时仍应保留自己的配置，不能以示例值覆盖。
