# Codex-QQ-AstrBotBridge

把本机已登录 ChatGPT 的 Codex CLI 接入 QQ 私聊和群聊的 AstrBot 插件，适用于同一台 Windows 电脑上的本地部署。

```text
QQ 普通账号 ⇄ NapCat ⇄ AstrBot / OneBot v11 ⇄ 本机 Codex CLI
```

私聊直接发文字，指定群内任何成员 @机器人即可聊天；`/new` 显式开启自己的新会话。插件不要求填写 OpenAI API Key。v0.3 起可开启“接入 AstrBot 插件和人格”，由插件自动注册本机 Codex 提供商，复用 AstrBot 的人格、插件钩子和工具执行流程。

## 支持范围

| 项目 | 当前行为 |
| --- | --- |
| 私聊 | 只响应配置的个人 QQ 账号 |
| 群聊 | 只响应配置的一个群，任何成员必须实际 @机器人 |
| 连续对话 | 按平台、聊天和发送者分别保存，私聊与群聊互不串联 |
| 群公共记忆 | 可选共享本群近期公开聊天，保留每条 QQ 身份；配合 LivingMemory `group` 模式共享本群长期事实 |
| 新会话 | 私聊 `/new`；群聊 `@机器人 /new` |
| 输入输出 | 直接模式支持文本；插件接入模式支持图片、按需视频抽帧摘要、生图和语音回复；接收语音并转文字仍需另配 STT |
| 并发 | 插件接入模式默认同时处理两个请求，超出后排队；直接模式一次一个，忙时提示重发 |
| 个性化 | 按 QQ 号选择关系、语气和回复习惯；区分当前发送者与本条真实 @ 的成员，分别匹配称呼和相处设置 |
| 回复速度 | 默认请求 Fast 模式，可关闭；不额外发送“稍等，我想一下” |
| 联网搜索 | 可选启用 Codex 自带的在线搜索和公开网页读取，无须另填搜索 API Key |
| 平台 | Windows 原生运行，AstrBot 的 OneBot v11（`aiocqhttp`）适配器 |

机器人显示为登录 NapCat 的 QQ 账号，头像、昵称和群内身份由该账号决定。账号需通过正常流程加入目标群；此链路不使用 QQ 官方机器人的 Webhook。

## 准备环境

- AstrBot `>=4.29.1,<5`，安装在 Windows 本机。
- NapCat 已登录用作机器人的 QQ 账号。
- 同一个 Windows 用户下安装 Codex CLI，并完成 **Sign in with ChatGPT** 登录。
- 已验证组合：Windows、Python 3.12、AstrBot 4.29.1、Codex CLI 0.162.0。其他 CLI 版本需确认支持本文使用的参数和功能开关。
- 视频抽帧和 Edge TTS 音频转换需要 `ffmpeg`；视频还需要同目录的 `ffprobe`。插件依赖由 `requirements.txt` 声明，包含 `edge-tts>=7.3.1,<8`；图片验证使用 AstrBot 环境中的 Pillow。

如果已经安装 Node.js，可以在 PowerShell 安装并检查 Codex：

```powershell
npm install -g @openai/codex
codex login
codex login status
codex --version
```

`login status` 应显示 `Logged in using ChatGPT`。本插件拒绝 API Key 登录模式，使用已登录账号的 Codex 额度，受账号权限和用量限制影响。ChatGPT 订阅不是通用的 API Key；本插件调用官方 CLI，不提取、转换或转发登录令牌。参见 [Codex 安装与登录说明](https://github.com/openai/codex#readme)。

AstrBot、NapCat 和 Codex 必须能在同一台电脑上正常运行。当前版本不能直接把 Windows 宿主机的 `codex.exe` 路径填进 Linux 或 Docker 里的 AstrBot。

## 1. 连接 NapCat 与 AstrBot

以下地址适用于两者运行在同一台 Windows 电脑的情况。

1. 在 AstrBot 的“机器人”页面创建 **OneBot v11** 实例并启用。
2. 反向 WebSocket 主机填 `127.0.0.1`，端口填 `6199`，设置自己的 Token。
3. 在 NapCat 的网络配置中新增并启用 **WebSocket 客户端**。
4. URL 填 `ws://127.0.0.1:6199/ws`，Token 与 AstrBot 完全一致；消息格式选 `array`，保存配置。
5. 用个人 QQ 私聊机器人发送 `/help`，先确认 AstrBot 能正常回复。

更多说明见 [AstrBot OneBot v11 接入文档](https://docs.astrbot.app/platform/aiocqhttp.html) 和 [NapCat 项目](https://github.com/NapNeko/NapCatQQ)。

## 2. 安装插件

在 AstrBot 的插件页面选择通过仓库链接安装，填入：

```text
https://github.com/Quin520/Codex-QQ-AstrBotBridge
```

也可以在 GitHub 点击 **Code → Download ZIP**，然后在 AstrBot 中通过本地文件安装。仓库根目录含 `metadata.yaml`、`main.py` 和 `_conf_schema.json`，可直接作为插件安装。

插件名称为“本机 Codex 桥接”，内部名称为 `astrbot_plugin_local_codex`。如果此前用本地 ZIP 安装过，请更新同名插件，避免手工复制出多个实例。

## 3. 填写插件配置

公开版不预填任何个人 QQ、群号或电脑路径。安装后打开插件配置：

| 配置项 | 如何填写 |
| --- | --- |
| `owner_qq` / 你的 QQ 号 | 填个人 QQ 号，**不是机器人 QQ 号**；必填，留空时所有消息都不处理 |
| `group_qq` / 允许使用的 QQ 群号 | 填一个目标群号；留空则只允许个人私聊，不支持“所有群”或多个群号 |
| `codex_exe` / 本机 Codex 程序路径 | 原生 `codex.exe` 的完整绝对路径，不是 `codex.cmd`、`codex.ps1` 或目录 |
| `model` / Codex 模型 | 建议先留空，使用 CLI 内置默认模型；手动填写时使用当前账号可用的模型 ID |
| `integrate_plugins` / 接入 AstrBot 插件和人格 | 需要使用其他 AI 插件时开启；自动创建并选用 `local_codex` 提供商，默认关闭以兼容旧版 |
| `enforce_owner_permissions` / 仅本人可管理 AstrBot，禁止普通成员访问本机 | 可选，默认关闭；接入模式下将此实例管理员设为 `owner_qq`，普通成员本机文件范围设为 `none`，关闭其 Shell、Python 与执行网络权限。影响实例内其他机器人，启用前会备份原值 |
| `fast_mode` / 默认启用 Codex Fast 模式 | 默认开启，关闭时请求 Standard 速度；不改变思考深度 |
| `web_search` / 允许 Codex 联网搜索 | 默认关闭；开启后使用 Codex 服务端在线搜索，不开放本机命令和文件权限 |
| `reasoning_effort` / Codex 推理等级 | 默认 `low`，还可选 `medium`、`high`、`xhigh`；需要所选模型支持 |
| `max_parallel_requests` / 并发请求数 | 插件接入模式默认 2，范围 1–4；让聊天和自学习等后台请求可以同时运行 |
| `group_context_enabled` / 共享目标群的近期公开聊天 | 默认关闭；开启后记住本群公开文字及机器人回复，供不同成员接续同一话题 |
| `group_context_max_messages` / 最多条数 | 默认 40，范围 2–100，每条最多 800 字符 |
| `group_context_max_chars` / 每次注入字符上限 | 默认 6000，范围 1000–16000；越大请求越长 |
| `group_context_max_minutes` / 保留分钟数 | 默认 360，范围 5–1440；过期记录下次使用或载入时清理 |
| `video_summary_enabled` / 分析视频画面并记入本群上下文 | 默认关闭；处理当前消息或同会话引用的 QQ 视频附件，群内必须实际 @机器人 |
| `video_ffmpeg_path` / ffmpeg 路径 | 可留空；优先查找 AstrBot Python 目录，其次 PATH；同目录需要 `ffprobe` |
| `video_max_seconds` / 最多分析前多少秒 | 默认 60，范围 1–60；超出的部分不分析，并在摘要注明 |
| `video_max_mb` / 下载大小上限 | 默认 50 MB，范围 1–50；不接收聊天指定的本地路径或内网视频地址 |
| `image_generation_enabled` / 允许 Codex CLI 按需生图 | 默认关闭；通过已登录 CLI 生成新图片，发回当前会话；不自动用于主动发言 |
| `image_generation_cooldown_seconds` / 生图间隔 | 默认 60 秒，范围 10–3600；同群所有成员共享冷却，全实例同时只处理一次生图 |
| `voice_enabled` / 允许按需语音回复 | 默认关闭；向模型提供短语音工具，普通回复仍为文字 |
| `voice_tts_provider_id` / 语音提供商 ID | 填已启用的 TTS 提供商 ID；可独立于全局自动 TTS 使用，留空跟随会话 TTS 设置 |
| `voice_max_chars` / 语音字符上限 | 默认 300，范围 40–500；一次回复最多一条语音 |
| `voice_cooldown_seconds` / 语音间隔 | 默认 30 秒，范围 5–600；同群所有成员共享冷却 |
| `relationship_presets` / 关系预设（可编辑） | 亲密、朋友、讨厌、不熟悉各有一段默认描述，可直接修改；应用于选用对应关系且未填写专属描述的成员 |
| `user_profiles` / 按 QQ 号配置称呼与相处方式 | 展开或添加“QQ 用户”，设置关系、称呼、相处习惯与自定义内容；默认没有个人资料 |
| `timeout_seconds` / 超时 | 默认 180 秒，范围 30–600 秒 |

### 查找原生 codex.exe

如果通过独立安装包安装，在 PowerShell 尝试：

```powershell
Get-Command codex.exe -ErrorAction SilentlyContinue |
    Select-Object -ExpandProperty Source
```

如果通过 npm 全局安装，用下面的命令查找：

```powershell
$codexPackage = Join-Path ((npm root -g).Trim()) '@openai\codex'
Get-ChildItem -LiteralPath $codexPackage -Filter codex.exe -Recurse |
    Select-Object -ExpandProperty FullName
```

把输出中与你的 Windows 架构匹配的原生 `.exe` 路径填到插件里；通常位于带 `win32-x64` 或 `win32-arm64` 的目录下。若没有结果，先完成 Codex 安装。

保存配置并重载插件。模型名称以当前账号在 Codex 中能使用的模型为准；不要填写“Pro”“ChatGPT”或套餐名称。插件使用 `--ignore-user-config`，不会读取个人 `config.toml` 中的模型和工具配置。

开启插件接入模式后，请在本插件中调整 Fast、推理等级和并发数。AstrBot 可能将模型与提供商配置拆开保存；v0.3.2 会更新对应的提供商配置，重启后仍可正常加载。

Fast 模式通过每次调用传入 `service_tier="fast"` 和 `features.fast_mode=true` 请求，不改动个人 Codex 设置。支持情况取决于模型和账号；Fast 会更快消耗订阅额度，当前倍率见 [Codex 官方速度说明](https://learn.chatgpt.com/docs/agent-configuration/speed)。

推理等级通过 `model_reasoning_effort` 单独配置，日常聊天建议 `low`，复杂分析时再选较高等级；它和 Fast 是两个独立参数。若模型本来就默认 `low`，显式选择 `low` 不会再次降低推理等级。后台插件会增加模型调用次数；默认并发 2 可减少排队，但不保证固定回复秒数，也不会增加账号额度。参数说明见 [Codex 官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

### 联网搜索

在“本机 Codex 桥接”配置中打开“允许 Codex 联网搜索”，保存后重启 AstrBot。随后私聊或在目标群 @机器人，发送例如“请先联网查找 AstrBot 的最新发布信息，并附上来源链接”。不需要另填搜索 API Key，也不需要开启 AstrBot 的电脑能力。

该开关每次向 CLI 显式传入 `web_search="live"`；关闭时传入 `web_search="disabled"`。搜索由 Codex 的服务端工具处理，与本机命令联网权限相互独立；不启用本机浏览器、文件读取、Shell 或 Python，也不改变群聊插件工具名单。参考 [Codex 网页搜索说明](https://learn.chatgpt.com/docs/web-search)。

这是桥接自己的搜索能力，不受 AstrBot“网页搜索提供商”开关控制。搜索会使用当前 Codex 账号额度并增加响应时间，是否搜索由模型根据问题决定；明确要求“先搜索再回答”更容易触发。网页打不开、需要登录或搜索失败时，不能保证取得内容。检索词和要读取的公开网址会提交给搜索服务；网页内容作为参考资料，不应当作工具授权或系统指令。

### 视频画面摘要

先开启“接入 AstrBot 插件和人格”，确认 `local_codex` 可用，再打开“分析视频画面并记入本群上下文”。在目标群发送视频并 @机器人，或引用同群的视频消息后发送 `@机器人 这个视频里发生了什么？`。主人私聊也可直接发送或引用视频。没有 @机器人的群视频不会自动下载和分析；不处理普通网址中的视频网页。

插件从当前会话可验证的 QQ 视频附件下载视频，默认上限 50 MB，最多取前 60 秒的 6 张画面，缩放后交给 Codex 生成视觉摘要，再回答问题。长视频只分析前段；抽帧可能漏掉短暂动作，不做音轨识别，不能凭画面声称听到了对白或歌声。下载、抽帧及模型失败会明确说明，临时视频与图片在处理结束后清理。

同时开启“共享目标群的近期公开聊天”时，摘要以视频原发送者的 QQ 和昵称归档，其他群员可接着问“刚才那个视频呢”。保存的是文字摘要，不是原视频或下载地址；私聊摘要不会加入群上下文。该功能会额外使用一次 Codex 识图调用并增加回复时间。

### 用 Codex 订阅生成新图片

开启插件接入模式和“允许 Codex CLI 按需生图”，然后发送 `@机器人 画一只戴黄色围巾的小企鹅，简洁卡通头像`。无需另建生图 API 账户、填写 API Key 或安装本地绘图模型；专用工作进程调用当前 Codex CLI 的原生生图能力，完成后由 AstrBot 转为 QQ 图片。能力和用量受已登录账号限制，参见 [Codex 图片生成说明](https://learn.chatgpt.com/docs/image-generation)。

在 AstrBot 配置中将“工具调用超时时间（秒）” `agent_runner.config.misc.tool_call_timeout` 调整为至少 **300 秒**；生图工作进程自身超时为 240 秒，外层超时过短会先中断任务。生图沿用桥接的模型、Fast 与推理等级，每次描述最多 1500 字符，返回一张图片。同群默认间隔 60 秒，正在生图时新请求会提示稍后再试。主动消息不能自动触发生图。

目前只支持从文字生成新图，不支持引用图片修改。普通聊天的 CLI 原生生图工具保持关闭，生图专用进程只允许受限空目录的文件读取，禁用本地命令、浏览器、个人规则和外部插件；底层无法执行文件限制时拒绝读取，不退回无限制运行。结果仅从本次新会话的固定产物目录取出并校验，不接受模型提供的任意本机路径。相关机制见 [Codex 权限配置](https://learn.chatgpt.com/docs/permissions)。

### Edge TTS 语音祝福与主动问候

1. 用 AstrBot 实际运行的 Python 安装本仓库依赖：`python -m pip install -r requirements.txt`；确认该进程能找到 `ffmpeg`。
2. 在 AstrBot 模型提供商页面添加 **Edge TTS** 并启用，可使用 `zh-CN-XiaoxiaoNeural` 音色、默认语速和音调。记下这条提供商的 ID，例如 `qq_edge_tts`。
3. 桥接中开启“允许按需语音回复”，把该 ID 填入 `voice_tts_provider_id`。AstrBot 的**全局自动 TTS 保持关闭**，这样文字聊天和按需语音可以并存。
4. 保存并重启 AstrBot，私聊或在群里 @机器人说“用语音祝我生日快乐”“用语音对我说晚安”。

Edge TTS 无需 API Key，但属于微软在线服务：**需要朗读的文本会发送至该服务**，不是本地离线合成。音色与连通性受服务状态影响。插件一次最多发送一条短语音，默认 300 字、同群间隔 30 秒；合成或发送失败时不会声称已成功发送。源码与音色查询方法见 [edge-tts 项目](https://github.com/rany2/edge-tts)。

安装本仓库更新后的[主动消息兼容补丁](compat/proactive_chat/README.md)，并允许目标群主动发言后，模型也可按人格和场景选择简短语音问候。桥接不新增计时器，启停主动消息插件仍控制自动发言。关闭主动消息插件好友和群聊设置中的“启用 TTS”（`friend_settings.tts_settings.enable_tts`、`group_settings.tts_settings.enable_tts`），由按需语音工具决定发送时机。

这项功能是朗读，适合祝福和问候，不能把“听你唱歌”变成真正的歌唱。播放现成歌曲继续用听歌插件；生成新的歌声需要另外接入音乐生成能力。接收 QQ 语音并理解内容则需要 STT，与这里的语音输出分开配置。

### 接入已下载的插件

1. 开启桥接配置中的“接入 AstrBot 插件和人格”，保存。
2. 第一次切换后重启 AstrBot，使模型配置、会话隔离和缓存的消息流程设置一起生效。
3. 在插件页面启用要使用的插件。需要选择聊天模型的插件，选择 **本机 Codex（ChatGPT 登录）**，提供商 ID 为 `local_codex`。

接入后的链路是：AstrBot 构造人格与历史 → 插件修改请求 → Codex 返回文本或工具调用 → AstrBot 执行插件工具 → Codex 根据结果继续回复 → 插件处理回复。命令插件仍由各自的命令触发，不会自动变成模型工具。

| 插件类型 / 例子 | 配置和限制 |
| --- | --- |
| 听歌插件 | 启用插件即可注册搜歌、点歌等工具；第三方音源的登录或服务要求仍由该插件负责 |
| 链接解析插件 | 保留消息处理流程；按该插件的解析开关、白名单和命令工作 |
| 自学习插件 | 打开它的 LLM 钩子，将筛选、提炼和强化模型选为 `local_codex`，并配置采集对象 |
| 表情包管理器 | 回复中的分类标签会保留给插件处理；先导入有图片的图包。要覆盖主动消息和插件请求，将 `generation.trigger.scope` 设为 `chat_and_plugin_llm`。视觉模型可用 `local_codex`；向量检索还需要 Embedding 提供商 |
| 主动消息插件 | 1.2.6 需安装[会话与模型流程兼容补丁](compat/proactive_chat/README.md)，再启用群聊、配置目标群并打开自动触发。插件列表的启用/停用控制自动发言 |
| 群分析总结插件 | v0.3.7 支持其 `response_format` JSON Schema（含数组）并校验返回值；定时或增量分析须另配群白名单、时间和最低消息量。群成员不能通过模型查询任意群的报告 |
| LivingMemory | 总结模型可选 `local_codex`，还必须配置独立的 Embedding 提供商；缺少它时插件不能完成初始化。2.7.1 可安装[群白名单及群记忆补丁](compat/livingmemory/README.md)。只读召回按真实事件及配置作用域执行，群成员不可调用记忆写入、删除工具 |

主动消息的目标必须与桥接允许的群一致。会话标识使用实际 OneBot 平台 ID，例如 `你的平台ID:GroupMessage:你的群号`。主动消息的频率、静默时段和无人回应次数由该插件设置；桥接不会额外创建定时器，也不会在它停用后另行主动发言。机器人正常接受 @提问不受“主动消息”插件开关影响。

主动插件的“群沉默时长”和“随机发送间隔”会相加：例如沉默 30 分钟、随机间隔 90–360 分钟，通常要连续安静约 2–6.5 小时才到发送时点，之后还会检查免打扰及无人回应限制。成员发言会重新计时。兼容补丁将群计时器合并到群级 UMO，普通聊天仍按成员隔离，并从同平台、同群读取最近的真实消息流水。不要为解决主动消息问题关闭全局会话隔离。

LivingMemory 与自学习承担不同任务：前者保存与召回历史事实、偏好和约定；后者调整表达并提出个人设置建议。LivingMemory 的记忆不会自动成为桥接的个人设置审批项。建议限制其采集白名单，保留 `use_session_filtering`；不要为了提高召回量而把所有群和私聊合并为全局记忆。新服务和模型需要独立配置，本仓库不捆绑它们。

### 分辨群员，同时接续群里的话题

保持 AstrBot 的群成员会话隔离，再打开桥接的“共享目标群的近期公开聊天”。例如 Alpha 在群里说周六骑车，Beta 接着问“他约的几点”，机器人可以参考同群上下文，同时知道当前提问者是 Beta，不会把 Alpha 的经历当成 Beta 的经历。真实 QQ 号用于区分成员，昵称仅用于展示；个人相处设置按明确标注的成员分别使用，不能相互套用。

近期上下文包含目标群没有 @机器人的普通文字及已发送的机器人文字回复，记录时间、QQ、昵称和回复对象；不读取私聊、其他群、其他平台实例或本机文件。命令、图片地址、附件路径与转发消息正文不收录。启用视频分析后可收录已生成的视觉摘要，成功发送的语音也记录其朗读文字。默认保留最近 40 条、最长 6 小时，每次只附带最近约 6000 字符；普通文字无需额外总结调用，但会增加当前请求长度。记录保存在本地 `group_context.json`，更新和重载后可继续使用；首次开启从后续消息开始，不会倒读历史。

更久的公共事实由 LivingMemory 保存：安装本仓库 v0.3.8 附带的累计兼容补丁后，将 `filtering_settings.memory_scope_mode` 选为 `group`，同时保持群白名单、会话和人格过滤。新生成的同群摘要共享给本群成员，原始总结窗口仍按成员分别积累，达到其总结条件后才形成长期记忆；私聊继续独立。不要选择 `global` 或关闭会话过滤来实现群共享。旧版累计记忆仍在原作用域，不会自动搬入群记忆；迁移应在停止 AstrBot 后，仅选择已核实属于同一平台实例、同一群的精确来源，并备份数据。

`/new` 仍只重开个人对话，不会遗忘群公共事实。公开聊天与记忆属于参考资料，不能修改管理员权限或自动批准个人设置变更。关闭公共上下文开关即停止新增和注入近期记录；如需清空本地记录，先停止 AstrBot 再删除桥接数据目录的 `group_context.json`。长期记忆由 LivingMemory 单独管理。

插件接入会把 AstrBot 实例的默认聊天模型设为 `local_codex`、开启群内按发送者隔离，并关闭工具状态提示；原值保存在桥接数据目录的 `settings-before-provider.json`。原直接模式的 Codex 历史不会导入，新聊天使用 AstrBot 自己的历史。关闭接入或卸载后，若需恢复原模型及会话设置，请在 AstrBot 配置中按备份恢复。

群聊模型工具按下文“QQ 权限边界”中的名单开放；其他下载插件工具仅允许所有者私聊使用。不提供 AstrBot 内置的文件、Shell、定时任务和跨会话发送工具。下载插件仍有自身的能力和权限，应使用自己信任的插件。此桥接不是通用 API 服务，不提供 Embedding 或 STT；语音输出复用单独配置的 AstrBot TTS 提供商。

### 设置每个人的称呼与相处方式

打开“本机 Codex 桥接”配置 → “按 QQ 号配置称呼与相处方式”，展开已有成员或添加“QQ 用户”。每个 QQ 号只填写一条，折叠时显示已填写的称呼。

关系可以选择“亲密、朋友、讨厌、不熟悉”，也可选择“沿用人格”或“自定义”。四种关系的默认含义如下，完整描述都能在同一配置页的“关系预设（可编辑）”中修改：

| 关系 | 预设的相处方式 |
| --- | --- |
| 亲密 | 放松温暖、自然关心和接梗，尊重边界；不自动设定恋爱关系或编造共同经历 |
| 朋友 | 平等、轻松、直接，可以表达不同意见，正事认真回答 |
| 讨厌 | 冷淡克制、保持距离、不主动亲近，正常问题仍准确回答，不辱骂或编造指责 |
| 不熟悉 | 自然礼貌、保持距离，不装熟、不默认接受互怼 |

“这个人的专属相处描述”留空时使用对应预设；填写后**替代**该预设，只影响这个人。修改通用预设不会覆盖已有个人描述。选择“自定义”时也在这里填写。选择“沿用人格”并留空描述，不额外指定关系。

每人还可以单独选择日常语气、回复长度、玩笑程度、认真求助和情绪低落时的回应方式，以及不用于玩笑的话题（多选）。“自定义相处规则”用于补充或调整这些选项；明确边界始终优先于玩笑设置。回复长度是默认习惯，对方当次明确提出的需求优先。

“已确认的共同经历与偏好”手动保存真实信息，不会自动写入；“回复风格示例”可填写“对方说……／理想回复……”来示范口语风格，示例不当成真实经历。原有“偏好标签”继续有效，明确的个人规则优先于笼统标签。

例如，给某位成员选择“朋友”“自然口语，少套话，不固定反问”“允许轻度互怼，认真时停止”，勾选“收入与工作”，并在自定义规则中写“只调侃拖延，不评价工作能力”。在管理页面保存时 AstrBot 会自动重载桥接，下一次回复应用新设置。历史对话影响较大时可发送 `/new`。

升级保留已有称呼和标签；新增选项默认“沿用人格”或留空，不自动为成员分配关系。设置不改变访问权限，也不会向模型提供整张用户表。群聊按当前发言者应用配置，并单独识别本条真实 @ 的成员；面向整个群的主动消息不使用成员个人配置。`/new` 清空当前会话的上下文，保留所有个人配置。

### 在同一条消息中 @其他成员

在 QQ 中实际选择 `@机器人 @某位成员 你会怎么称呼他？`，桥接会按该成员真实 QQ 读取已配置的称呼、标签和必要相处规则，同时保留谁在提问、每个 @ 在消息中的位置。同名群员、不同群昵称、连续 @多人或重复 @同一人都按 QQ 区分。没有配置的成员只标明真实提及身份，不编造关系。此能力不依赖群公共上下文开关，也不会增加成员查询或模型调用。

被提及不代表对方正在发言。回复提问者继续使用提问者的设置；实际对被提及者说话时才使用该成员的相处规则，不主动公开内部标签、关系评级或配置内容。被提及者的“共同经历与偏好”、回复示例和私聊历史不随 @ 加入请求。不要在称呼、标签或相处规则中填写不希望参与群聊处理的私人信息。

手打 `@昵称`、`@全体成员`、引用或转发消息内部的 @ 不会自动匹配个人配置。群消息仍须实际 @机器人才能触发普通回复；涉及多个人时，明确写清“让谁做什么”有助于理解指代。

### 从聊天学习个人相处设置（v0.3.6）

这是可选功能，公开版默认关闭。先安装 [自学习插件 4.3.1 兼容补丁](compat/self_learning/README.md)，然后打开桥接配置中的“从自学习插件生成个人设置审批建议”。每个成员也有“允许为此人提出学习建议”开关。

自学习原有的采集过滤器先决定是否接收消息，桥接再限制为目标群或所有者私聊中已配置的成员。分析会读取该成员当前的关系、专属描述和其他选项，以及已解析的关系预设；不会把其他人的资料一起传入个人分析。默认先合并 20 秒，同一成员每 300 秒最多分析一批、每批最近 12 条，所有成员的个人分析串行执行，不在正常回复链路中等待。

进入**自学习管理页 → 审查队列 → 人格与个人设置**，即可看到成员、字段、修改前后内容和原始聊天依据。可以修改建议值后批准，也可拒绝或删除。列表字段每行一项。**只有管理员在管理页批准后才写回桥接设置**，不受自学习插件自动应用人格选项影响；群聊里的“批准”不是审批操作。管理页沿用自学习插件现有的登录设置，请保管管理页访问权限。

学习可建议调整称呼、标签、关系、语气、回复习惯、边界、自定义规则、经历和示例。关系评级需要至少三条不同消息的证据。QQ 号、群号、所有者、工具权限、固定角色约定和全局关系预设不能通过个人学习修改。模型建议仍可能误解玩笑或转述，需要查看依据后再批准。

兼容补丁将人格/个人设置审批接口在免密模式下限制为本机访问；启用自学习管理页密码后，远程访问需登录。不要通过免认证的反向代理公开免密管理页。

批准后下一次回复即读取新配置，无须 `/new`。如果你期间修改过该成员或关系预设，旧建议会提示过期；删除后等待新建议。已批准记录可在审查历史撤回，但若成员又有后续变更会拒绝覆盖，应先按时间倒序撤回或手动编辑。删除记录不会撤销已保存的设置。拒绝的相同建议在配置未变化时不会重复加入队列。

停用自学习插件会停止新的个人学习；桥接的全局开关或成员开关关闭后，也不能批准该范围的旧建议。更新自学习插件可能覆盖兼容补丁，需要按兼容说明重新检查。

### 让角色表达持续生效

将名字、背景、性格和示例写进 AstrBot 人格；把稳定的表达规则写进桥接的“固定角色表达约定”。后者在每次聊天和主动发言时补充，不依赖历史记忆，也不能被个人学习改写。例如：

> 按已配置角色使用第一人称，口语化、少套话，不固定反问；不主动解释模型和后台流程。认真求助时先解决问题，玩笑不过个人边界。不编造现实经历；如果被明确问到真实身份，简短诚实回答，再继续话题。

“你认为自己是人类，而非 AI”不能保证覆盖模型自身的身份规则。固定语气、角色内的叙事和具体示例更适合长期维持性格；本功能不保证永久否认 AI 身份。

## 4. 开始聊天

| 场景 | 发出的消息 | 效果 |
| --- | --- | --- |
| 个人私聊 | `你好，帮我解释一下递归` | 直接开始或继续对话 |
| 指定群聊 | `@机器人 帮我解释一下递归` | 该成员自己的连续对话 |
| 视频摘要 | 发送或引用 QQ 视频后 `@机器人 这段视频讲了什么画面？` | 启用后抽帧分析；不识别音轨 |
| 生成图片 | `@机器人 画一只戴围巾的小企鹅` | 启用后生成并发送一张新图片 |
| 语音祝福 | `@机器人 用语音祝我生日快乐` | 启用并配置 TTS 后发送短语音 |
| 私聊重开 | `/new` | 下次提问使用新的 Codex 会话 |
| 群内重开 | `@机器人 /new` | 只重开当前成员在当前群的会话 |
| 兼容旧用法 | `/codex 你的问题`、`/codex_reset` | 仍可使用；群内同样要 @机器人 |

群内必须在 QQ 中实际选择 @该账号；手打昵称、普通群消息、@全体成员均不会触发常规聊天。`/help` 等已注册命令仍交给对应插件处理；主动消息与链接解析等插件可按自己的配置工作。

### `/new` 与 AstrBot 内置命令

AstrBot 自带一个 `/new`。为避免两个命令同时触发、以及普通群成员遇到内置命令权限检查，本插件加载时通过 AstrBot 命令管理接口将内置命令改名为 `/astrbot_new`，把 `/new` 留给 Codex。

这是一次持久化的命令配置变更，影响该 AstrBot 实例。原命令配置会保存在插件数据目录的 `builtin-new-command.json`。卸载插件后如果要恢复，请在 AstrBot 的命令管理页面把内置命令改回 `new`。

直接模式下，`/new` 只移除当前聊天中自己的 Codex 会话映射；插件接入模式下，它创建并选中自己的新 AstrBot 会话。两种模式都不删除旧历史，也不清空其他成员的上下文。重启后会话保留；插件不使用 `resume --last`，不会主动接续桌面上其他 Codex 对话。

## 数据与隐私

仓库只包含源码、空配置模板、文档和使用虚构身份的测试，不需要上传真实配置、聊天记录或登录文件。

### QQ 权限边界

群聊只向模型开放已启用点歌插件的 `find_music`、`deliver_music`、`search_music`，表情包插件的 `search_memes`，LivingMemory `recall_long_term_memory`，以及本桥接的 `send_voice`、`generate_image`。记忆召回按真实事件的会话或本群作用域检索，模型不能指定其他群或他人私聊；需在 LivingMemory 中保留会话过滤。语音和生图需分别开启，只能发送到当前事件所属会话，工具参数不包含接收人或文件路径。工具名称与来源插件必须同时匹配；新安装的插件不会自动获得群聊模型工具权限。自学习和主动消息的已有事件流程仍由各自插件配置控制。

其他下载插件的模型工具仅可由 `owner_qq` 的私聊使用，执行前会再次核对当前 QQ 身份及插件状态。群主、群管理员、昵称和消息中的身份声明不能获得此权限；所有者在群中发言也使用群聊工具范围。聊天身份依据 OneBot 事件，请保护 OneBot Token 并让连接端口仅供本机使用。

CLI 的电脑、命令和本地文件相关工具仍关闭，AstrBot 内置文件、Shell、Python、跨会话发送、MCP 和子智能体工具也不会通过桥接开放。开启“仅本人可管理 AstrBot，禁止普通成员访问本机”会额外设置 AstrBot 的管理员和普通成员权限，**不会**启用 QQ 远程操作电脑。所有者的 Codex 桌面使用不受影响。

这些是应用层权限，无法替代操作系统隔离：下载插件仍以 AstrBot 所在 Windows 账户运行，其命令处理器和事件钩子不属于模型工具校验范围。需要防范插件漏洞或恶意插件时，应将群聊实例放到独立虚拟机中，不共享项目目录、个人配置或宿主机剪贴板；“只读共享”仍然允许读取代码。另见 [AstrBot 本机能力说明](https://docs.astrbot.app/faq.html) 与 [Windows Sandbox 隔离及共享配置](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file)。

运行时数据主要位于 AstrBot 数据目录中：

| 相对路径 | 内容 |
| --- | --- |
| `data/config/astrbot_plugin_local_codex_config.json` | 本机路径、个人 QQ、群号、称呼和标签等配置 |
| `data/plugin_data/astrbot_plugin_local_codex/sessions.json` | 聊天与发送者到 Codex 会话 ID 的映射 |
| 同目录的 `group_context.json` | 开启公共上下文时保存的有限群文字、QQ、昵称、时间与回复对象；不随插件发布 |
| 同目录的 `last-run.jsonl`、`last-error.log` | 最近一次已结束调用的输出与错误诊断，可能包含回复内容或本机信息 |
| 同目录的 `builtin-new-command.json` | 修改前的 AstrBot 内置命令配置 |
| 同目录的 `workspace/` | 插件专用工作目录 |
| 同目录的 `provider/` | 插件接入模式的最近一次调用日志、独立工作目录；临时请求及附件在调用结束时清理 |
| 同目录的 `video-work/` | 视频分析临时目录；单次下载与抽帧文件在处理结束时清理，文字摘要可进入群上下文 |
| 同目录的 `image_generation/` | 生图调用日志、空工作目录及 `outgoing/` 中的图片副本；输出图片保留在本机 |
| 同目录的 `settings-before-provider.json` | 启用提供商前的默认模型、会话隔离与工具状态设置 |
| 同目录的 `settings-before-permissions.json` | 首次启用权限限制前的管理员列表及本机工具权限，仅保存在本机 |
| 同目录的 `profile-reviews.json` | 个人设置建议、聊天依据、审批历史与写入恢复日志，含成员资料 |
| 同目录的 `profile-config-backups/` | 每次审批写入前的完整桥接配置备份，仅保存在本机 |

Codex 自身管理登录数据。直接模式保留 CLI 会话；插件接入模式使用 `--ephemeral`，由 AstrBot 保存历史。QQ 中提交的文字、图片、视频抽帧、生图描述、当前用户偏好、本条真实 @ 成员的必要配置以及启用插件附加的上下文会传给已登录的 Codex 服务，回复会回到对应私聊或群聊。启用 Edge TTS 后，待朗读文本另发至微软语音服务，音频由 AstrBot 临时目录保存。主动消息、自学习等插件可按自己的设置读取群历史；群聊回复对群成员可见。

普通调用使用只读沙箱、独立工作目录、标准输入传递提示词，并关闭 CLI 的本地命令执行、应用、浏览器、电脑操作、任意图片读取、原生插件、生图和多智能体等工具。明确附在消息中的图片可通过 `--image` 输入；生图专用调用单独使用仅限空工作目录的文件权限，并只启用原生生图。AstrBot 插件工具由 AstrBot 执行。这些限制依赖各组件实现，不等同于操作系统级完全隔离。

Codex 原生生成的图片还会保留在 `CODEX_HOME/generated_images/<会话ID>/`，默认是当前用户的 `.codex/generated_images/`；桥接复制图片发送，不删除原件。此目录与插件 `image_generation/outgoing/` 均可能包含用户创作，不能当作源码上传，需按本机数据保留需求管理。

`.gitignore` 已排除常见配置、日志、数据库、登录文件和运行目录。反馈问题时只提供脱敏后的错误片段；不要上传完整 AstrBot 数据目录、Codex 登录文件或真实聊天日志。

## 常见问题

“我想听歌！”插件提示未检测到 ffmpeg 时，需要在 AstrBot 所在电脑安装。Windows 可用 `winget install --id Gyan.FFmpeg.Essentials --exact --source winget`；该构建提供方列在 [FFmpeg 官方下载页](https://ffmpeg.org/download.html)。安装后重启启动器和 AstrBot，让进程拿到更新的 PATH。该听歌插件在初始化时缓存检测结果，因此程序安装好后还需重载插件；可先用 `ffmpeg -version` 验证程序本身。

| 现象 | 检查顺序 |
| --- | --- |
| `/help` 也不回复 | 确认 QQ 在线、NapCat WebSocket **客户端**已启用、两端地址和 Token 一致；查看 AstrBot 是否显示 OneBot 已连接及是否限制了消息唤醒 |
| `/help` 正常，聊天不回复 | 确认插件已启用并重载，`owner_qq` 已填，私聊来自该账号，群号正确且实际 @了机器人 |
| `/new` 提示管理员权限或触发了两个回复 | 查看插件加载日志及命令管理，确认内置命令已改为 `/astrbot_new`，检查其他插件是否也注册了 `new` |
| 提示登录失败 | 在运行 AstrBot 的同一 Windows 用户下执行 `codex login`，选择 ChatGPT 登录，再检查 `codex login status` |
| 程序路径错误 | 填原生 `.exe` 的完整路径；Codex 更新后重新确认路径 |
| 模型不可用 | 先将 `model` 留空；指定模型时确认当前账号拥有该模型权限 |
| 提示未知参数或功能开关 | 核对 CLI 版本；本版在 0.162.0 验证过，不要通过关闭沙箱或启用执行工具解决 |
| 提示忙或超时 | 等上一条完成后重发；按需增加超时秒数。超时会停止本插件启动的子进程 |
| 额度不足、限流或请求失败 | 查看本地错误日志中的实际原因；订阅用量和服务限制仍然适用 |
| 上下文异常 | 发送 `/new`，再重新提问 |
| AI 插件没有生效 | 确认“接入 AstrBot 插件和人格”已开启，重启后存在 `local_codex`，插件本身启用并正确选择模型 |
| 机器人说不能联网 | 打开桥接中的“允许 Codex 联网搜索”并重启；新会话中明确要求搜索并提供来源。只开启 AstrBot 原生搜索开关不会绕过桥接工具权限 |
| 视频没有摘要 | 确认接入模式与视频开关已开启，实际 @了机器人，发送或引用的是当前会话 QQ 视频附件，`ffmpeg` / `ffprobe` 可用且大小未超限 |
| 生图超时或只有文字 | 确认生图已开启、CLI 支持原生生图及文件权限，AstrBot 工具调用超时至少 300 秒；检查 `image_generation/last-error.log`，不要通过开放本机读取解决 |
| 没有语音或每条都变语音 | 确认桥接语音开关、明确的 TTS 提供商 ID、Edge TTS 提供商启用、依赖与 ffmpeg 可用；按需模式关闭全局和主动插件的自动 TTS |
| v0.3.0 私聊只有自学习日志，没有正式回复 | 升级到 v0.3.1 并重启 AstrBot；旧版错误设置了 AstrBot 的默认模型请求抑制标志 |
| 重启后桥接插件加载报 `KeyError: 'type'` | 升级到 v0.3.2 并重启 AstrBot；旧版没有正确读取 AstrBot 拆分保存的提供商配置 |
| 表情包没发出 | 检查图包实际包含图片并启用；主动消息或插件请求还需 `chat_and_plugin_llm` 范围，配图本身是按需生成 |
| 主动消息没发出 | 先检查 1.2.6 兼容补丁，再检查目标群、自动触发、沉默与随机等待时长、免打扰和无人回应限制 |
| 群分析 JSON 解析失败 | 升级 v0.3.7；若仍报错，检查实际 schema/返回格式。桥接会明确报告不符合约束的输出，不伪装成成功 |
| LivingMemory 等待提供商或初始化失败 | 为它同时配置聊天与 Embedding 提供商；Codex CLI 登录不提供 Embedding 接口 |

默认的直接模式不经过 AstrBot 模型流程，需要其他 AI 插件时请开启接入模式。电脑、AstrBot 和 NapCat 需要持续运行才能回复；各插件自身的额外依赖仍需配置。

## 开发与验证

使用已经安装 AstrBot 依赖的 Python 3.12 环境，在本仓库根目录执行。若 AstrBot 源码未安装到 Python 路径中，先将其源码根目录加入 `PYTHONPATH`：

```powershell
$env:PYTHONPATH = 'D:\Apps\AstrBot'
python -m unittest discover -s tests -t . -v
```

将示例路径替换为自己的 AstrBot 源码位置，并确认 `python` 是该 AstrBot 环境的解释器。测试将 AstrBot 数据根目录指向临时目录，使用虚构 QQ 身份，不调用真实 Codex、不发送 QQ 消息、不修改运行中的配置。

回归测试覆盖访问范围、实际 @判断、会话隔离、新会话、命令保留、内置命令迁移、真实唤醒/消息处理/回复阶段、子进程参数与标准输入、Fast 与推理参数、登录与超时、提供商真实装载/重载、并发及取消、工具参数校验、个人关系预设与覆盖、真实配置保存/重载、当前用户资料和主动消息范围。v0.3.9 另覆盖视频来源与下载限制、抽帧、语音提供商和发送范围、生图权限参数、产物校验与同群冷却。
